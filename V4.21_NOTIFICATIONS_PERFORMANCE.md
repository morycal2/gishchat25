# Zento v4.21 — notifications, command switch & performance

- Bot chats now have a bottom `دکمه‌ها` switch beside emoji to show/hide the latest reply keyboard.
- Bot command messages are rendered as clickable command links.
- Socket.IO prefers WebSocket and falls back to polling; chat list refresh is debounced instead of reloading after every message.
- Message send/receive animation and lightweight local notification sounds are enabled according to notification settings.
- Settings now include notification sound selection and a dedicated `تماس‌ها` section for ringtone, volume and conference tone.
- Browser notification permission can be enabled from settings.
- Web Push subscriptions are stored in PostgreSQL and server-side push delivery is supported when VAPID variables are configured.
- Incoming call alerts are sent as push notifications when a browser/device has an active Web Push subscription. The actual WebRTC call still requires the app/browser to wake and establish signaling.

## Railway environment variables

Set:

- `VAPID_PUBLIC_KEY`
- `VAPID_PRIVATE_KEY`
- `VAPID_SUBJECT` (for example `mailto:admin@example.com`)

Also set `window.ZENTO_CONFIG.VAPID_PUBLIC_KEY` in `public/config.js` to the same public key.

Run the SQL in `database/v4.21_notifications.sql` once against the production database.
