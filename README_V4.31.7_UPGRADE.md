# Zento v4.31.7 — Announcements & Service Controls Fix

این نسخه بر پایه `Zento-v4.31.6-Moderation-Announcements-ServiceControls.zip` ساخته شده است.

## تغییرات
- بخش **اطلاعیه‌ها** برای کاربران فعال است و اطلاعیه‌های فعال را نمایش می‌دهد.
- در پنل مدیریت، بخش **مدیریت اطلاعیه‌ها** شامل فهرست اطلاعیه‌های قبلی، ویرایش، فعال/مخفی‌کردن و حذف است.
- **کنترل سرویس‌ها** در سمت سرور تقویت شد؛ خاموش‌کردن پیام‌ها دیگر فقط UI نیست و مسیر REST ارسال/فوروارد پیام نیز آن را مسدود می‌کند.
- کنترل استوری، تماس، پشتیبانی، ربات‌ها و تاریخچه تماس نیز در مسیرهای مربوطه اعمال شده است.
- وضعیت کنترل سرویس برای کلاینت از `/api/service-status` خوانده می‌شود و UI نیز هم‌زمان با وضعیت سرور غیرفعال می‌شود.
- WebSocket هنگام غیرفعال‌سازی کلی اجازه اتصال کاربران عادی را نمی‌دهد؛ سازنده/مدیر از کنترل مدیریتی خارج نمی‌شود.
- **کنفرانس از چت‌های خصوصی حذف شد** و فقط برای گفتگوهای گروهی/کانالی قابل نمایش است.
- حتی اگر تابع کنفرانس به‌صورت برنامه‌ای صدا زده شود، چت خصوصی اجازه شروع کنفرانس ندارد.
- شماره نسخه پروژه به `4.31.7` ارتقا یافت.

## نکته Railway
پس از Deploy، برای تست خاموش‌کردن پیام‌ها:
1. پنل سازنده → کنترل سرویس → پیام‌ها → خاموش.
2. با یک حساب کاربری معمولی یک پیام متنی یا فایل ارسال کن.
3. باید ارسال از سرور با خطای «ارسال پیام موقتاً غیرفعال است» رد شود؛ حتی اگر کلاینت قدیمی/Socket هنوز باز باشد.


## تعمیر خطاهای HTTP 503 در نسخه Fix
اگر `/api/messages` یا `/api/stories/feed` برای کاربران معمولی با `503` برمی‌گردد،
یعنی یکی از کنترل‌های سرویس در جدول `site_controls` خاموش است. برای فعال‌کردن دوباره
همه سرویس‌ها، روی سرور اجرا کنید:

```bash
npm run repair:services
```

این دستور فقط وضعیت کنترل سرویس‌ها را به حالت فعال برمی‌گرداند و پیام‌ها/کاربران را حذف نمی‌کند.

## درباره خطای 403 حساب «اطلاع‌رسانی»
حساب سیستمی `admin` عمداً حساب اطلاع‌رسانی است و نباید گفتگوی خصوصی، ارسال پیام عادی
یا تماس داشته باشد. این رفتار امنیتی است و حذف نشده است. همچنین ادمین‌های فعال پنل از
قفل کنترل سرویس‌ها برای تست مدیریتی مستثنا شده‌اند.
