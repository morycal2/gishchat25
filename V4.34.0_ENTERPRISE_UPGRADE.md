# Zento v4.34.0 — Enterprise Upgrade

## Added
- Enterprise health/API layer.
- PostgreSQL-backed global search for users, conversations and accessible messages.
- WebCrypto ECDH P-256 device identity and AES-GCM conversation encryption primitives.
- E2EE device registry, conversation security state and encrypted key envelopes.
- Dedicated encrypted-message endpoint that stores ciphertext only in `messages.e2ee_payload`.
- Multi-device encryption device management and revocation.
- Conversation roles with JSON permission sets and role membership.
- User data export endpoint for backup/portability.
- Enterprise floating control center in the web client.
- Capacitor configuration for the Android packaging phase.
- Additional PostgreSQL indexes for conversation/message retrieval.

## Important security note
E2EE is opt-in per conversation. Existing normal messages remain normal messages. The enterprise UI provides explicit E2EE activation and encrypted-message sending; it does not falsely claim that every existing message has become end-to-end encrypted.

For production-grade E2EE, the next hardening step is automatic per-recipient device key envelopes with verified identity/fingerprint UX, key rotation, multi-device recovery and encrypted attachment streaming.

## Railway
No new mandatory external service is required for this upgrade. PostgreSQL remains the primary database. Redis is intentionally not mandatory in this version so the deployment remains compatible with the existing Railway setup.

## Android
`capacitor.config.json` is included. A native Android project can be generated with Capacitor in a local development environment after installing the Capacitor CLI/dependencies.
